# RC Quartermaster website

Procurement-focused website for RC Quartermaster LLC: browse an approved product catalogue, search, and submit a Request for Quote (RFQ). There is no cart, checkout or payment processing.

Stack: Next.js (App Router) + TypeScript + Tailwind CSS, Payload CMS 3 inside the same app, PostgreSQL, S3-compatible storage (Cloudflare R2), Resend, Cloudflare Turnstile, React Hook Form + Zod, Vitest, Playwright + axe. Hosted on Vercel.

## Quick start (local development)

Requirements: Node.js 20.9+ (22 recommended), npm, Docker (for local PostgreSQL).

```bash
npm install
cp .env.example .env            # then set PAYLOAD_SECRET, IP_HASH_SALT, CRON_SECRET (openssl rand -hex 32)
echo "DB_PUSH=true" >> .env     # let Payload create/update tables automatically in local dev
docker compose up -d            # PostgreSQL on localhost:5432
npm run seed                    # sample data: 4 categories, 20 products, pages, dev users
npm run dev                     # http://localhost:3000  (admin: http://localhost:3000/admin)
```

Seeded development users (never created in production): `admin@example.com`, `catalogue@example.com`, `sales@example.com`, password `ChangeMe-12345!` (override with `SEED_PASSWORD`).

Seed data is fictitious. Do not load it into production.

Reset everything locally: `docker compose down -v && rm -rf .data && docker compose up -d && npm run seed`.

## Scripts

| Command                                      | What it does                                                      |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `npm run dev` / `build` / `start`            | Next.js dev server, production build, production server           |
| `npm run lint` / `typecheck` / `format:check`| ESLint (includes jsx-a11y), TypeScript strict, Prettier           |
| `npm test`                                   | Vitest unit tests                                                 |
| `npm run test:e2e`                           | Playwright end-to-end and axe accessibility tests                 |
| `npm run seed`                               | Idempotent sample data (`npm run seed -- force` to override the production guard) |
| `npm run import:csv -- file.csv [dry-run] [publish]` | Bulk product import (see the admin guide for the template) |
| `npm run reindex`                            | Rebuild the search index from published products                  |
| `npm run migrate` / `migrate:create <name>`  | Apply / generate database migrations                              |
| `npm run generate:types` / `generate:importmap` | Regenerate Payload types and admin component map after config changes |

Note: the Payload CLI strips `--flags` from script arguments, so script options are bare words (`dry-run`, `publish`, `stop-on-error`, `force`) or environment variables (`IMPORT_DRY_RUN=1`, `IMPORT_PUBLISH=1`, `FORCE_SEED=1`).

## Project layout

```
src/
  app/(site)/        public pages (home, categories, products, search, rfq, content pages, 404)
  app/(payload)/     Payload admin and REST API (generated by Payload)
  app/api/           RFQ submit and upload-url, attachment download, cron jobs, CSV import/export, health
  collections/       Payload collections (users, categories, products, documents, rfqs, ...)
  globals/           Site settings
  access/            role helpers used by every access rule
  lib/               domain code: search, rfq, security, storage, mail, csv, data loaders
  components/        UI components (accessibility-first) and admin components
  config/redirects.json   301 redirect map (placeholder until the URL audit is done)
  migrations/        reviewed database migrations (committed)
scripts/             seed, CSV import, reindex
tests/unit, tests/e2e
docs/
```

## Key conventions

- **Published only**: public code reads through Payload access control (`overrideAccess: false`) and filters on published status again. Never read catalogue data with override access in a public path.
- **Provider interfaces**: `SearchService`/`SearchIndexer`, `PrivateStorage`, `Mailer`, `AttachmentScanner` are small interfaces. Swapping a vendor means adding one implementation and one line in a factory.
- **Shared validation**: `src/lib/rfq/schema.ts` is used by the browser form and the server route. The server is authoritative.
- **Schema changes**: edit the collection, run `npm run migrate:create <name>`, review the generated SQL, commit it. Production applies migrations with `npm run migrate`; it never uses auto-push.
- **Redirects**: add entries to `src/config/redirects.json`; they are served as 301.
- **Accessibility**: new UI must pass axe in `tests/e2e/accessibility.spec.ts` and keep tokens in `src/app/(site)/globals.css` above AA contrast (checked by `tests/unit/contrast.test.ts`).
- **Dependencies**: only add packages with a reason; see the dependency register in docs/ARCHITECTURE.md section 11.

## Testing

`npm test` runs unit tests (fast, no services). `npm run test:e2e` needs PostgreSQL and seeded data; it builds on a running dev server or starts one. In CI the app is built and started first. Playwright uses Cloudflare's public Turnstile test keys, the console email adapter and the local storage driver.

## Security notes

Secrets live only in environment variables (see `.env.example`; `.env` is git-ignored). Report vulnerabilities to the site owner privately. See docs/ARCHITECTURE.md section 7 for the threat model and docs/DEPLOYMENT.md for production hardening.
